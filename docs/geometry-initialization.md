# Host-driven geometry initialization

This internal [issue #18](https://github.com/tylerstuff/strata/issues/18) prerequisite lets a host initialize several cooked terrain providers through the existing `GeometryPageCache` under one budget. `GeometryPageCache.begin()` and `GpuGeometry.begin()` return initialization handles. Existing `create()` calls remain eager, with their original options and behavior; this is not a public scene API or a world-streaming implementation.

The aggregate upload guarantee covers **initialization only**: packed metadata, initial selections, authenticated root pages (all pages in resident modes), and final residency tables. Normal `prepare()` page/table/uniform writes retain their existing behavior and are outside this shared upload allowance. Host initialization accepts default terrain rendering only, rejecting extra rendering arguments/options. It therefore introduces no eager 64-byte terrain uniform write. Optional rendering through existing `create()` remains available.

`GeometryTransferBudget` requires fixed limits for `maxRequests`, `pageStagingBytes`, `transientBytes`, `residentBytes`, `gpuBufferBytes`, and `uploadBytesPerFrame`. All are safe integers; requests are at least one, page staging and frame upload capacity at least 65,536 bytes, other byte limits nonnegative, and upload capacity four-byte aligned. Impossible reservations fail; temporary contention leaves initialization pending.

The trusted host calls `beginFrame(id)` once per physical frame and shares that allowance among initializers. IDs must be strictly increasing nonnegative safe integers; renewal expires older allowances. Initialization never renews automatically. Foreign or expired frames are rejected before initialization side effects. Metadata writes use four-byte-aligned chunks; page writes remain whole pages. Consuming the allowance pauses further writes until the host advances with capacity.

Admission atomically reserves provider storage, cache storage, and transient packing storage before owned allocation or compilation. The provider drains metadata and initial-selection uploads before advancing root loading, releases their transient reservation, then writes the final residency table after complete roots. Separate transient/page limits and a minimum one-page staging capacity let roots progress without waiting for their own metadata reservation. Readiness requires every required page and initialization write, plus both pipelines.

The host path accepts at most 8,192 pages, 256 tiles, 262,144 clusters and eight LODs per tile. Total page references and cluster references each cannot exceed the cluster count; parsed unique ownership and existing format validation remain required. These count caps do not change ordinary scene admission.

Reservations describe logical owned typed-array storage and requested `GPUBuffer` sizes. With metadata bytes `M`, page count `P`, tile count `T`, and `F` the sum of each tile's maximum LOD triangle count, the provider reserves `M + 4P + 128T + 8F + 416` GPU bytes. The cache separately reserves its pool. Actual triangle capacity can be smaller than `F`, so this reservation may exceed requested buffers; provider telemetry exposes both. Resident CPU reservations cover cache slot/mapping arrays and provider residency, frame, argument and light arrays. Transient reservation includes metadata, selections and typed packing scratch.

The caller supplies an already-parsed manifest. Its objects, general JS heap, fetch/network buffers, compiler and driver allocations are excluded. This does not bound world metadata decoding. Reservations persist with their owner until disposal; temporary storage is released when no longer owned. Release is not a claim about physical garbage collection.

Handles expose `status`, `error`, `revision`, `advance(frame)`, `waitForChange(revision)`, `takeReady()` and `dispose()`. Statuses are `pending`, `ready`, `failed`, `taken` and `disposed`. Inspect `error` on failure/cancellation; terminal waits resolve. Revision checks prevent missed notifications; observers run in coalesced microtasks. `takeReady()` transfers ownership once and detaches creation cancellation. Disposing that handle afterward leaves the provider intact. Canceled requests retain their slots/payload reservations until settlement; canceled pipeline work retains its initializer reservations until all started compilations settle. Late work cannot publish a disposed provider.

Counters record used/peak logical reservations and bytes accepted by successful `queue.writeBuffer` calls, not GPU completion. Synchronous write failures refund their allowance; earlier successful writes remain counted.

CPU tests use unchanged cooker seeds 42–45, hashed response streams, actual caches and a recording fake GPU queue. The larger fixture has 82,852 metadata bytes and verifies uploads spanning multiple 65,536-byte frames. Tests cover shared limits, legacy byte equivalence, delayed/failed operations, partial-write failure, cancellation and disposal. They establish no browser/WebGPU, performance or complete `npm run check` result. A world index/coordinator, composite selection, shared anchors, shadow/temporal/depth behavior and streamed tracing proxies remain subsequent work.

Setting `STRATA_CPU_INITIALIZATION_REPORT_DIR` to an absolute directory outside the repository emits optional CPU admission/write receipts for the shared-source and large-metadata tests. These contain counts, hashes and accounting; generated source pages stay in temporary directories and are removed after testing. No receipts are written by default.
