# Initial M2 browser baseline — 2026-09-05

The procedural diffuse scene sustained approximately 60 browser callbacks per second on the available M2 MacBook Air at 720p and 1080p. This establishes a small-scene baseline. It does not demonstrate PBR, virtualized geometry, GI, reflections, a representative game workload, or the final Switch 2-inspired visual target.

## Configuration

- Source: `64623f05b75497c87f48f82238ac689be16a768c`, clean checkout for both sessions. This exact revision is retained in the benchmark PR history.
- MacBook Air Mac14,15, Apple M2, 10-core GPU, 8-core CPU, 16 GB shared system memory. Browser adapter: vendor `apple`, architecture `metal-3`, fallback `false`; detailed device/description strings were unavailable.
- macOS 26.5.2 (25F84), Darwin 25.5.0 arm64; Node 22.23.0; installed Chrome 152.0.7977.82, headed temporary profile, no launch flags.
- AC power, battery 100%, AC Low Power Mode **off** throughout all 32 power observations. Battery-mode preference remained on but was inactive.
- Built-in panel identifier reports 2880×1864 Retina. The OS reports scaled desktop 1920×1243 at 60 Hz and composited pixel size 3840×2486. The automated browser viewport/screen is 1920×1160 at device scale factor 1. Internal render sizes are fixed independently at 1280×720 and 1920×1080; timed canvas CSS size is 1280×720. Post-capture PNGs use the native internal render sizes.
- `procedural-boxes-v1`, seed 1337, 512 boxes plus ground, 6,156 triangles, one instanced draw, no dispatches, diffuse directional shading/depth. Camera `orbit-20s-v1`; render path `diffuse-raster-v1`. No external assets loaded.
- Each run uses 30 seconds of warm-up. Normal captures last 60 seconds per resolution; sustained capture lasts 180 seconds at 1080p. Read [the protocol](../benchmark.md) for interpretation and reproduction commands.

## Recorded timings

All timings below are milliseconds. RAF intervals measure callback cadence; GPU pass timestamps exclude presentation and are visibly quantized. These are individual captures, not a confidence interval or a hardware capacity estimate.

| Run | Frames | Mean callback FPS | RAF p50 / p95 / p99 | CPU submission p95 | GPU pass p50 / p95 / p99 |
| --- | ---: | ---: | --- | ---: | --- |
| 1280×720 / 60 s | 3,601 | 60.00 | 16.70 / 17.70 / 18.30 | 0.40 | 0.131 / 1.311 / 2.884 |
| 1920×1080 / 60 s | 3,600 | 60.00 | 16.70 / 17.30 / 17.60 | 0.50 | 0.459 / 0.459 / 0.524 |
| 1920×1080 / 180 s sustained | 10,800 | 60.00 | 16.70 / 17.40 / 17.60 | 0.40 | 0.393 / 0.459 / 0.524 |

All runs had zero callback intervals above 20 ms, zero dropped/pending GPU samples and zero uncaptured GPU errors. Every captured frame had a GPU timestamp sample. The 720p run had a wider GPU tail than 1080p; do not infer resolution scaling from one pair of captures. Browser/GPU scheduling, clock state and quantization are not isolated by this experiment. Repeat matched sessions when a claimed change is near this variability.

Cold engine initialization took 9.3 / 10.7 / 9.2 ms for the three runs; scene creation/compilation took 3.4 / 1.5 / 2.7 ms. This does not clear OS/driver shader caches.

Each scene initially uploads 25,464 bytes, followed by 64 camera-uniform bytes per frame. Requested GPU buffers total 25,656 bytes, including 128 profiling bytes. Requested depth texture payload is 3,686,400 bytes at 720p and 8,294,400 bytes at 1080p. WASM linear memory is 1,114,112 bytes. Geometry is entirely resident; there is no model streaming. These are application-owned payloads, not measured total VRAM or physical residency.

The sustained run collected 16 power/thermal observations. All reported AC Low Power Mode off and no recorded thermal/performance warnings. Temperature was unavailable. This establishes no warning observed during this modest workload; it does not prove that a heavier workload cannot throttle.
