# World-space diffuse GI — 2026-09-05

The two-room GI proof produced offscreen color transfer with a bounded software BVH/probe workload. On the MacBook Air M2, GI-on p95 GPU span was **3.87 ms at 720p and 6.95 ms at 1080p**, compared with 1.18 and 2.29 ms with GI disabled. These spans cover the earliest through latest recorded pass boundary, not browser presentation or all GPU work. The scene is only 132 opaque triangles; its receiver remains dim, interpolation is patchy and changes take many submissions to stabilize. Neither a representative game's 60 FPS performance nor the visual target is established.

## Reproduction and scope

All four performance runs used clean source `135877e8c45052e6535a5eabf9cbf96e85c3e460`, with the original compute GI composition. Hardware: MacBook Air Mac14,15, Apple M2 with 10 GPU cores and 8 CPU cores, 16 GB shared memory, macOS 26.5.2 / Darwin 25.5.0, headed Chrome 152.0.7977.82 and Node 22.23.0. WebGPU reported Apple / metal-3 and a non-fallback adapter. The viewport was 1920×1160, DPR 1, with a 1280×720 CSS canvas and explicit 1280×720 or 1920×1080 render targets.

Each resolution had 30 seconds of warm-up and 60 seconds of measurement. The overview camera stayed fixed; TAA was enabled, shadow resolution was 2048², seed was 1337, and the GI budget was 32 probe updates ×64 primary rays per submission, plus at most 2,048 shadow queries. There are 384 probes and one diffuse bounce. The 60-second scenario starts with an open door/red wall/full light, closes the door at 10 seconds, reopens it at 20, dims the light to 0.2 at 30, restores it at 40, and changes the wall to neutral at 50. Both modes received the same changes. The raw reports record the first submitted frame after each event.

```sh
npm ci
npm run build
npm run benchmark -- --renderer gi --gi off --camera overview --gi-scenario door-light --require-ac-performance
npm run benchmark -- --renderer gi --gi on --camera overview --gi-scenario door-light --require-ac-performance
```

These are sequential single captures, not confidence intervals. All 32 before/during/after power observations confirmed AC Power with active Low Power Mode 0; the inactive battery profile remained 1. No thermal/performance warning was recorded, but actual temperatures were unavailable and these observations do not rule out throttling or changes entirely between samples.

## Timings: preserve overlapping intervals

GPU pass timestamps overlap on this adapter. Adding their durations does **not** measure elapsed GPU frame time. The profiler now records relative start/end boundaries after subtracting the uint64 origin, and the report validates each frame's envelope independently of its pass sum. Every timed frame in these captures had a sum larger than its span.

The span includes gaps within its earliest/latest recorded boundaries, but excludes the probe-atlas preservation copies before the first timed pass, earlier uploads, browser composition and scan-out. It is not a presentation fence, a utilization measure, or uncapped throughput. WebGPU timestamp placement and command scheduling also prevent treating the difference between two pass timings as an isolated kernel cost; see the [GPUWeb timestamp discussion](https://github.com/gpuweb/gpuweb/wiki/GPU-Web-2023-11-08#problem-measuring-time-deltas-with-writetimestamp-3952). Observed timestamp steps were 0.065536 ms.

All values below are milliseconds; percentiles use nearest rank.

These are overlapping interval durations. In particular, the larger TAA/presentation intervals with GI enabled do not prove those shaders themselves became correspondingly more expensive. The fixed-size trace/update workload scales differently from full-resolution composition, but a bottleneck decision needs isolated or controlled end-to-end experiments. An exploratory fragment-composition variant produced identical rendered measurements and the same 6.685 ms 1080p median span in short controls; no meaningful speedup was demonstrated, so compute composition was retained.

Older GI reports from source `32de637` have pass sums only. Their approximately 19.4 ms 1080p sum must not be described as elapsed frame time or evidence that the 16.67 ms target was missed. Earlier raster/geometry reports have the same measurement limitation and cannot reconstruct a span retroactively.

## Allocation, uploads and startup

Requested GPU buffer payload was 99,088 bytes in every run, including the 1,024-byte profiler. Texture payload was:

| GI / resolution | Tracked GPU texture bytes | MiB |
| --- | ---: | ---: |
| Off / 720p | 63,012,864 | 60.09 |
| Off / 1080p | 118,308,864 | 112.83 |
| On / 720p | 70,385,664 | 67.13 |
| On / 1080p | 134,897,664 | 128.65 |

The fixed GI resources total 2,049,472 bytes: 11,392 trace bytes, 71,904 probe buffer bytes, 1,966,080 probe texture bytes and a 96-byte composition uniform. Composition adds an 8-byte-per-pixel HDR target. Disabling GI retains its scene-owned trace/cache resources; a fresh GI-off run never allocates that composition target. These are app-requested payloads, not physical residency or total VRAM. They exclude driver/browser allocations, swapchain, JavaScript heap and query-set overhead. WASM linear memory stayed at 1,114,112 bytes.

Initial uploads were 58,448 bytes. Measurement-window uploads were 1,453,840 bytes for off/720p, 1,454,224 for off/1080p (one extra frame), and 2,317,200 for each GI-on run, including the scenario changes. Each active GI update also preserves 983,040 bytes between probe atlases using GPU copies before `gi-trace`; these copies are not included in the reported span or upload counter. TAA-on submissions used four draws, 266 submitted triangles including shadows/fullscreen work, and zero/off or three/on compute dispatches.

Initialization took 10.8–13.1 ms; first scene creation per browser took 21.4/23.0 ms for off/on and the subsequent resolution took 4.8/5.0 ms. These are API-observed startup samples with potentially warm browser/driver caches, not cold-OS guarantees. Renderer chunks keep GI out of the default package startup path; packed HTML/Vite and SSR/type checks verify that separation.

## Quality and representation evidence

The clean functional and isolated representation tests used source `32de6374e7a0aa18823f12a63e4f0c63de29dbd6`; the later change adds timing/report instrumentation and smoke-run bounds without changing the GI renderer. The [GI guide](../gi.md) gives exact geometry, thresholds, CPU witnesses, shader layouts and limitations.

- Across 8,192 test rays over both door states, BVH closest-hit and any-hit agreed with the independent CPU reference with no exhausted traversals. The bounded analytic-box SDF exhausted 743/1,024 open-door and 757/1,024 closed-door grazing queries, plus some other cases. This supports the BVH for this fixture; it is not a conclusion about all SDF implementations. Isolated 4,096-ray BVH closest-hit medians were 0.654/0.671 ms versus SDF 0.700/0.674 ms; variability and correctness preclude a broad speedup claim.
- With the colored wall wholly offscreen, cold world/screen histories, TAA off and no screen tracing, the shadowed 25-pixel receiver region had zero direct RGB. The red-wall indirect tail mean was approximately `(0.002339, 0.000967, 0.000860)` versus neutral `(0.001728, 0.001640, 0.001511)`. Red/green changed from 1.054 to 2.417.
- The tested receiver was zero after closing the door and immediately after switching the light off. This is local evidence, not a leak-free scene guarantee. The unamplified receiver remains dark; the overview and ×20 indirect diagnostic reveal coarse interpolation/leakage patches.
- A receiver first responded on submission 5. Over a 240-submission observation, the final 24-frame energy variation was 2.46% red, 5.30% neutral and 12.42% after reopening. The first samples that subsequently stayed within ±20% of that short tail mean were 199/199/221. This retrospective finite-window check is not convergence against a ground-truth solution or measured display latency. At an actual 60 submissions/second, those frame counts would correspond to about 3.3–3.7 seconds.

The final performance PNGs reset the world at time zero and run 240 held-time GI-on updates outside measurement (off uses eight). Separate functional captures show direct/indirect/final, probe and tracing views. [Issue #15](https://github.com/tylerstuff/strata/issues/15) tracks reference-based error, faster response and spatial quality improvements. The next selective-reflection proof is [#6](https://github.com/tylerstuff/strata/issues/6); geometry/GI integration remains a later task.
