# Cooked terrain streaming — 2026-09-05

The 8 MiB streamed pool rendered terrain with 74.94 MiB of unique compiled pages while preserving coarse coverage. Tracked GPU buffer payload fell from the conventional reference's 70.80 MiB to 11.06 MiB, and CPU submission p95 fell from 1.60 to 0.60 ms. GPU pass-sum p95 increased from 5.37 to 6.36 ms at 720p and from 9.96 to 11.27 ms at 1080p. Streaming reduced memory and CPU submission cost in this experiment; it did not reduce the sum of recorded GPU pass intervals; elapsed GPU time was not measured. Requested detail was unavailable in 16.47% of sampled frames. This is a restricted analytic-heightfield proof, not a production geometry system or an integrated graphics result.

## Coverage, detail and traffic

GPU modes submit two indirect geometry draws plus two fullscreen draws; the conventional path submits 67–72 draws in total. Conventional culling is per tile; GPU culling additionally rejects clusters. Median selected main-view triangles were 98,304 for mesh and 12,032 for GPU modes, so they do not submit identical work. The close tour and conservative error bound select finest visible LODs whenever resident. Consequently resident LOD and resident finest make the same visible choices here; this run does not demonstrate resident LOD savings. All modes use coarse geometry for offscreen shadow casters.

At 720p/1080p, streamed page fetches during capture were 146,735,104 / 146,538,496 bytes, with 146,145,280 / 145,424,384 bytes uploaded and 2,230 / 2,219 evictions. End totals can include requests finishing during the bounded readback flush. Requests peaked at four and staging reservations at 262,144 bytes. There were zero failed pages, missing-coverage tiles or output overflows. This is actual repeated refinement and eviction of unique geometry, rather than instancing or whole-asset residency.

Both streamed captures reported missing requested detail in 593/3,600 frames (16.47%), with at most three affected tiles. Median conservative projected error was zero; p95 was 2,416 / 3,697 pixels, with maxima about 1.32 / 1.98 million pixels. **These are conservative approximation bounds, not measured pixel displacement.** The global analytic bound, near-plane projection and coarse fallback make them very loose. The 2-pixel request is not maintained while detail is absent. Refined-to-coarse changes can pop; the retained boundary topology preserves coverage but cannot hide that change. Smaller refinement units, tighter errors and better retention/prefetch policy need further work. Reduced shadow triangles and missing detail also prevent interpreting streamed-vs-resident GPU timing as a pure cache-overhead comparison.

The separate delayed-load/camera-cut GPU harness checked 112,896 interior pixels per coverage image with zero holes through cold coarse state, partial refinement, eviction and abrupt cuts. CPU/GPU strict and coarse LOD choices agree. Locked boundary topology, positive winding and area/manifold checks provide additional evidence beyond the screenshot mask. Temporal history rejects LOD changes. A settled performance capture was visually inspected for continuous shaded/checkered terrain; these procedural images do not establish game-content visual quality.
