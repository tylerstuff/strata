# PBR and temporal baseline — 2026-09-05

The procedural PBR scene maintained approximately 60 browser callbacks per second in all four captures. At 1080p with temporal AA, the sum of the measured GPU passes was 4.59 ms at p95, with 110.95 MiB of tracked texture payload. These results cover 512 boxes plus ground, not representative game assets, virtual geometry, GI or reflections. The final visual/performance goal remains unverified.

## Repeatable settings

Measured clean source `40d2c9a748e0116f2e6f064d770dfde0a9095e42`. Hardware was the same MacBook Air M2 (10-core GPU, 16 GB), macOS 26.5.2 and headed Chrome 152.0.7977.82 as the [diffuse baseline](2026-09-05-m2-baseline.md). AC Low Power Mode remained off throughout all power observations; no thermal/performance warning was reported and temperature remained unavailable. Display/viewport settings, 30-second warm-up and 60-second capture per resolution match that protocol. These are individual captures, not confidence intervals.

The PBR fixture uses seed 1337, the same `orbit-20s-v1` camera and box layout, one animated box, generated base-color/metallic-roughness textures, 2048² directional shadows, HDR and tone mapping. Render path `pbr-shadow-temporal-v1` and all quality controls are recorded in raw results. Temporal processing uses an eight-sample jitter, per-tap depth-qualified history and neighborhood clamping. Read [the raster guide](../raster.md) for inputs, formats, limitations and comparison commands.

Percentiles of separate passes do not sum to the percentile of their frame-wise sum. At 1080p, temporal itself measured 1.51 ms at p95, while presentation also cost more in the temporal run. Presentation is currently the largest pass in that configuration and is a future optimization candidate; this experiment does not isolate its cause. The diffuse baseline's 1080p GPU p95 was 0.46 ms, but PBR changes several features together, so that difference is not the isolated cost of one effect.

Every measured frame had a complete set of GPU pass samples. All runs recorded zero intervals above 20 ms, zero GPU errors and zero dropped/pending samples. The shader/profiling checks also passed Linux software-WebGPU CI; those CI timings are not hardware evidence.

Requested GPU buffer payload was 26,360 bytes for each run, including 512 profiling bytes. Fresh TAA-off runs do not allocate history textures; toggling off after use retains history until replacement/disposal, so that transition has a different retained allocation. Initial GPU uploads were 58,232 bytes; steady frame uploads were 368 bytes without temporal or 384 with it. Scene geometry is 6,156 triangles; submission counters additionally count its shadow rendering and fullscreen passes. WASM linear memory remained 1,114,112 bytes. Allocation counters exclude swapchain, driver/browser memory and query-set overhead.

## Validation and local evidence

The production GGX distribution was numerically checked on the GPU for sharp, rough and grazing cases. Synthetic GPU tests checked signed in-bounds reprojection, depth discontinuities within a bilinear footprint, newly exposed surfaces, out-of-bounds motion, neighborhood clamping and explicit resets. Browser tests captured final/direct/shadow/depth/normal/motion/material views and verified resize, toggles, renderer replacement, failed-submission recovery logic and disposal. These tests establish the supported foundation, not artifact-free temporal reconstruction for arbitrary content.
